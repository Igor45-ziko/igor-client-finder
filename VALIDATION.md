# Проверка исправления 0.2.1 — 25 октября 2026

## Ошибка и исправление

На Windows пользователь сообщил о 30+ минутах ожидания Overture и неработающей отмене. В 0.2 таймер вызывал child.kill() только для родителя и ожидал close без второго таймаута. Официальный загрузчик собран PyInstaller --onefile и использует дочерний процесс. Сохранённые им потоки способны удерживать ожидание после уничтожения родителя. Это найденный дефект управления процессами; причина медленной сетевой выборки на компьютере пользователя без журнала не установлена.

Исправление: отдельная группа процесса, Windows taskkill /PID /T /F, Linux SIGKILL группы, отдельный предел ожидания остановки 6 секунд, очистка таймеров и потоков независимо от close. При неподтверждённом завершении дерева выводится PID и отключаются следующие загрузки Overture. Ctrl+C отменяет также каталог и установку загрузчика, не запускает новый город. CMD запускает Node напрямую.

Диагностика: этапы, PID, время и остаток 300-секундного бюджета, размер GeoJSON и давность вывода CLI. Файл не трактуется как счётчик сетевого трафика. Журнал diagnostics.log и начальный report.json создаются до обращения к источнику. Прежние outputs/.cache/.tools сохраняются, частичный GeoJSON не становится кэшем.

## Проверки исправления

- npm ci, npm run check — успешно в облачной Linux-среде, Node.js 24.
- **81 автоматический тест, 0 ошибок, 0 пропусков**: исходные 65 и 16 новых регрессий.
- Настоящие локальные родительский и дочерний процессы: таймаут и отмена прекращают запись дочернего процесса; сообщения после остановки не продолжаются. Оба теста также выполняются Windows-матрицей GitHub Actions.
- Отдельно: фактическая граница таймера 300 секунд с виртуальными часами; не закрывающиеся потоки; зависший/ошибочный taskkill; гонка close с отменой; лимит размера; запрет источника; отмена каталога/установки; сохранность старых данных; partial/interrupted отчёты и журнал.
- Набор включён в существующую CI-проверку Windows и Linux. Фактический статус нового коммита проверяется после публикации; см. Actions в репозитории.
- Упаковка проверяется повторной установкой, синтаксисом и всеми тестами в чистой распакованной папке.

Это локальные синтетические сценарии, не аудит реальных компаний. Повторный живой запрос Overture из облака не выполнялся: действует прежнее ограничение прокси. На Windows пользователя нужно повторить test-audit.cmd; новая версия диагностирует и ограничивает зависание, но не гарантирует доступность сервера или скорость выдачи.

# Проверка версии 0.2 — 25 октября 2026

## Что сохранено и доработано

Второй этап продолжен с сохранённых файлов. Первый поиск через Overpass сохранён. Новая команда использует последнюю непустую organizations.json, включая частичный поиск; повторный поиск компаний не требуется. Папки outputs, .cache и .tools не включаются в архив и не удаляются при запуске программы.

Добавлены независимые кандидаты сайтов из Overture Places, сопоставление с организацией, браузерные проверки Playwright, снимки 1440/390 px, CSV и HTML с доказательствами. Отдельные поля контактов восстанавливают VK/Telegram/MAX/телефон/email из старых записей и дополняются контактами только с подтверждённого сайта. Отправка сообщений не реализована.

## Проверки в рабочей среде

- Linux, Node.js 24.19.0, npm 11.9.0, системный Chromium.
- npm ci — успешно; npm run check проверяет синтаксис всех исходных модулей и скриптов.
- Автоматические тесты выполняются с PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm test.
- Итог в этой среде: **65 тестов пройдены, 0 ошибок, 0 пропусков**. Набор включает проверки первого этапа и настоящий Chromium на локальных тестовых страницах.
- Проверяются существующий поиск, обработка ошибок и кэш, независимое обнаружение сайта только в Overture, ложные совпадения, блокировки, публичность адресов, контактные поля, CSV, HTML и сохранность прежних результатов.
- Настоящий Playwright посещает локальный тестовый HTTP-сайт: подтверждает совпадающие данные, обнаруживает горизонтальное переполнение и HTTP 404, сохраняет скриншоты, соблюдает robots.txt и блокирует POST. Все тестовые организации явно вымышленные и существуют только в тестах/временных папках.
- Официальные загрузчики Overture 1.0.2 получены с GitHub Release и проверены SHA-256. Linux-загрузчик успешно выполнил --version и download --help. Это проверка инструмента, а не реальная выборка организаций.
- npm run setup:audit успешно запускает имеющийся Chromium; npm run audit -- --help работает.
- Добавлен GitHub Actions workflow для Windows и Linux: установка фиксированных зависимостей, Playwright, синтаксис, все тесты, запуск официального Overture executable с --version. Наличие workflow само по себе не означает его успешного прохождения; фактический статус проверяется в Actions после публикации.

## Что не выдаётся за проверенный результат

- Свежий запрос к stac.overturemaps.org/catalog.json блокируется прокси этой среды: 403 CONNECT. Native S3-загрузчик при заданном прокси не запускается, поскольку не гарантирует его соблюдения.
- Небольшой реальный аудит 5–10 организаций в этой среде не выполнен. Результаты тестов не являются результатами поиска клиентов. Нельзя утверждать, сколько сайтов Overture найдёт для конкретных российских организаций, до запуска на Windows.
- Пользователь сообщил об успешной работе версии 0.1 на Windows: Тверь 180, Тула 89, Рязань — таймаут, 19 кандидатов. Эти цифры здесь не перепроверены; исходная пользовательская выборка находится на его компьютере.
- Статус «Сайт не обнаружен, требуется подтверждение» ограничен успешно проверенными источниками и не доказывает отсутствие сайта в Интернете. Ошибка источника получает отдельный статус и не повышает приоритет.
- Совпадение телефона/названия/адреса — обоснование связи сайта, не юридическое доказательство владения доменом. Проблемы перед предложением услуги нужно подтвердить по снимкам и ссылкам.

## Испытание на Windows

Распаковать обновление в прежнюю папку, **не удаляя outputs и .cache**, затем открыть test-audit.cmd двойным щелчком. При первом запуске нужен Интернет для бесплатных компонентов и данных. После завершения открыть outputs/audit-.../report.html и shortlist.csv. Обычный запуск — start-audit.cmd.

Проект не обращается к репозиториям портфолио и не меняет их. Лицензии и ограничения данных описаны в SOURCES.md.

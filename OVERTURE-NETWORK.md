# Node.js и Overture CLI: техническое решение перед новым испытанием

26 октября 2026. Это исследование и предложение; новый загрузчик и большая выгрузка не запускались.

## Что установлено

Пользователь сообщил о пяти успешных сетевых проверках 0.2.2 на Windows: каталог STAC, первые 4 КБ STAC Parquet (206/PAR1), S3 ListObjectsV2 с одним ключом, запись Wikidata с P856 и JSON AllThePlaces. Валидация AllThePlaces ошибочно требовала groups. Плоский формат подтверждён официальным генератором ci/run_all_spiders.sh; исправлен в 0.2.3. Полный пользовательский sources.json в рабочую среду не передан; точные значения/времена не реконструировались.

Успешный ListObjectsV2 **не проверяет GetObject, чтение footer/row groups или скорость выгрузки района**. Начало STAC Parquet с PAR1 ещё не означает, что его полный индекс прочитан и разобран. Соединение с источниками подтверждено на пользовательском Windows по его результатам; покрытие организаций и поиск их сайтов — нет. Облачный прокси остаётся отдельным ограничением и не объясняет поведение Windows.

## Различия сетевых путей

| Путь | Что делает | Чем отличается |
| --- | --- | --- |
| Наша диагностика Node.js | fetch/Undici, --use-env-proxy, небольшие HTTPS-запросы | Явные AbortSignal, общий бюджет 45 с; тот стек, который успешно работал у пользователя. |
| Python внутри Overture CLI 1.0.2 | urllib.request.urlopen для каталога и collections.parquet | Каталог читается снова; весь STAC индекс сначала читается в память. В этих вызовах нет явного timeout. Свой TLS/прокси-путь Python; он не равен Undici. |
| PyArrow S3FileSystem внутри CLI | Нативный C++ AWS SDK: метаданные объектов, Range-чтение, Parquet scan | Отдельные настройки proxy_options, доверенных CA, повторов и соединений. CLI задаёт anonymous=True, region=us-west-2, connect_timeout/request_timeout, но не proxy_options/tls_ca_file_path/retry_strategy. |

В lockfile тега Overture v1.0.2 записан PyArrow 22.0.0; фактический состав EXE на Windows не измерялся. Документация Arrow 22: request_timeout — таймаут чтения сокета Windows/macOS, а не всего задания; стандартная стратегия S3 допускает до трёх попыток. В Overture включены batch_readahead=16, fragment_readahead=4 и потоки. Серия запросов/повторов может занимать намного больше одного request_timeout. Общий внешний таймаут и taskkill остаются обязательными.

Разница прокси, CA, AWS-запросов, распаковка/импорты EXE и чтение полного индекса — возможные причины задержки, **не установленный диагноз**. Нельзя заключать, что PyArrow заблокирован, только по общему таймауту CLI. Не следует отключать TLS, антивирус, обязательный прокси или переключаться на зеркала.

## Предлагаемый следующий шаг — малые проверки, а не район

1. Сохранить из успешного S3-ответа один фактический ключ Parquet. Через тот же Node.js выполнить HEAD и GET с Range последних 8 байт **этого же объекта**. Проверить HTTP 206, Content-Range, ETag/размер и PAR1 в конце. Лимит каждого запроса 8 с; никакого скачивания объекта целиком при проигнорированном Range.
2. Получить только ограниченный footer: максимум 256 КиБ. Если заявленная длина больше — остановиться с явной причиной, не расширять загрузку автоматически. Это проверит возможность читать Parquet, а не только видеть имя файла в бакете. Общий бюджет всей пробы — 45 с. Данные организаций при этом не запрашиваются.
3. Отдельно, без сети, проверить запуск установленного CLI командой --version с лимитом 10 с и прежней остановкой дерева. Это отделяет запуск PyInstaller/импорт библиотек от задержки сети. Обычный CLI не умеет принимать произвольный Python-код или выполнять такой же единичный S3-запрос; не предлагать пользователю несуществующий флаг.

Если требуется доказать причину именно в PyArrow, понадобится небольшой инструментированный проверочный процесс с теми же зависимостями: один GetObject/Range того же ключа, согласованные разрешённые прокси/CA, одна попытка и внешний таймаут. Сейчас такой процесс не реализован; запуск существующего полного CLI не заменяет сравнение одинаковых запросов.

## Предпочтительный вариант загрузчика после проверки

Сохранить проверенный HTTPS-транспорт Node.js: каталог и разрешённые Range-запросы выполняет Node с едиными прокси, TLS, журналом стадий, бюджетом времени/байтов и отменой. Parquet-метаданные обрабатываются локально совместимым JS-читателем. До интеграции отдельно проверить поддержку схем Overture, вложенных полей и сжатия; выбранная библиотека пока не установлена и совместимость не заявляется.

Это изменение реализации доступа к тому же разрешённому источнику, не обход отказов: при 403/429/ошибке TLS остановка без других адресов. Нельзя переходить к этому пути в облаке, где сам источник запрещён политикой. Предварительные проверки должны выполняться там, где доступ разрешён.

Только после успешной малой пробы: ограниченное чтение индекса/нужных колонок и групп для одной области с отдельным бюджетом. Затем настоящее сопоставление 5 организаций. До такого испытания независимый поиск сайтов не объявляется работающим. Overture остаётся дополнительным; обычный аудит известных сайтов и старые outputs/.cache не меняются.

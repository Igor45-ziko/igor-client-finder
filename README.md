# Игорь — поиск и проверка потенциальных клиентов, версия 0.2.3

Самостоятельно находит автосервисы в OpenStreetMap через Overpass API. Не требует списка компаний, ключей API, ChatGPT API, регистрации или платных подписок. Не отправляет сообщения, письма, заявки и не открывает контакты в приложениях.

Поиск и фильтрация выполняются программой; языковая модель и платные API не вызываются. Версия 0.2 добавляет независимый поиск сайтов в Overture Maps Places, сопоставление организаций и аудит Playwright. Персональные предложения и рассылки не реализованы.

## Исправление диагностики в 0.2.3

AllThePlaces поддерживает плоский манифест (`output_url`, `parquet_url`, `spiders`, `total_lines`) без `groups`. В 0.2.2 ошибочное требование `groups` давало `manifestValid: false` при рабочем HTTP 200. Теперь распознаются плоский и групповой форматы; проверяются счётчики и URL, в `sources.json` записываются `manifestFormat` и конкретные `manifestErrors`. Дополнительные поля допускаются. При пяти успешных проверках с корректными данными итог `complete` означает завершённую диагностику, **не успешный поиск клиентов**.

Пользователь подтвердил доступность пяти источников из Node.js на Windows. Это не повторено в облаке и не доказывает работу полной выборки через PyArrow. Большую выгрузку повторять не нужно. Различия сетевых путей и предлагаемый короткий следующий шаг описаны в [OVERTURE-NETWORK.md](OVERTURE-NETWORK.md). Новый загрузчик пока не внедрён.

## Что меняет 0.2.2

**Известные сайты проверяются сразу, без ожидания Overture.** После каждой организации сохраняются HTML, CSV и доказательства. Ошибка дополнительного каталога не отменяет уже подтверждённый сайт и не удаляет результаты. Если сайты всех выбранных организаций подтверждены, аудит может завершиться `complete` без Overture; это не утверждение о полноте поиска по Интернету.

По умолчанию Overture читает только пригодный семидневный кэш. Если его нет, программа не тратит пять минут на выгрузку: независимый поиск честно помечается незавершённым. Сайты из OSM и доменов корпоративной почты — отдельные кандидаты, **не новый независимый источник**. Контакты VK/Telegram/MAX сохраняются, но профиль в соцсети не приравнивается к самостоятельному сайту.

**Работающая замена Overture пока не подтверждена.** Wikidata и AllThePlaces исследованы, но свежие данные в облачной среде получить не удалось из-за `403 CONNECT` её прокси. Они не подключены как якобы проверенный поисковый источник. Эта версия ускоряет проверку известных сайтов и диагностику, а не обещает автоматически найти сайты всех небольших организаций. См. [SOURCES.md](SOURCES.md).

### Короткая диагностика — без повторного долгого запуска

Двойной щелчок по **`diagnose-sources.cmd`**. До 8 секунд на запрос, общий бюджет 45 секунд. Не устанавливает браузер/Overture, не запускает нативную выгрузку и не изменяет кэш. Проверяет каталог Overture, первые 4 КБ индекса, один ключ S3, опубликованную запись бренда в Wikidata и описание публикации AllThePlaces. Последующие запросы Overture пропускаются, если каталог недоступен. Обходов блокировок, повторов и зеркал нет.

Новый результат: `outputs/source-diagnostics-.../sources.json` и `README.txt`. При `403`/`429`, таймауте, ошибке TLS/DNS либо неподходящем ответе причина отмечается отдельно. Ответ 200 или получение одной записи **не доказывает полезное покрытие компаний Твери, Тулы и Рязани**. Для дальнейшей диагностики можно прислать `sources.json`, а также прежние `diagnostics.log` и `report.json` аудита (проверьте перед передачей локальные пути/контакты).

## Обновление и второй этап на Windows 11

Распакуйте новую версию в `D:\igor-client-finder`, заменив файлы программы. **Сохраните прежние папки `outputs` и `.cache`**: они содержат ваши найденные организации и кэш, в ZIP их нет. Если распаковали в другую папку, скопируйте туда старую `outputs`. Не требуется повторно искать 180 организаций Твери и 89 Тулы. Архив содержит верхнюю папку `igor-client-finder`: не создайте по ошибке двойную вложенность.

Первое небольшое испытание:

**Самый простой запуск: дважды щёлкните `test-audit.cmd`.** Проверятся до пяти организаций из последней сохранённой выборки. Окно сообщит об установке бесплатных компонентов и не закроется после завершения. Для обычной проверки до 60 организаций используйте `start-audit.cmd`.

Или выполните команду:

```powershell
cd D:\igor-client-finder
npm.cmd run audit -- --limit 5
```

Команда сама выберет последнюю **непустую** `organizations.json` из ваших результатов (подходит и частичный поиск, где Рязань завершилась таймаутом). Пустой неуспешный запуск не затрёт предыдущую выборку. Можно явно указать `--input "outputs/папка-запуска/organizations.json"`.

При первом запуске автоматически устанавливаются бесплатные библиотеки из зафиксированного `package-lock.json`. Используется установленный Microsoft Edge на Windows; если его нет, загружается Chromium Playwright. Только при явно выбранном `--overture online` для Overture скачивается официальный автономный загрузчик 1.0.2 (~56 МБ Windows x64), проверяется SHA-256. **Python, аккаунт AWS, ключи API, платные подписки не нужны.** Установка и географическая выгрузка могут занять несколько минут; трафик зависит от региона. Программа не скачивает весь мировой набор: bbox обязателен, есть таймаут и ограничение размера результата.

Полная проверка с бюджетом до 60 организаций и коротким списком до 20:

```powershell
npm.cmd run audit
```

Есть `start-audit.cmd` для двойного щелчка. Допустимы `--limit 1..300`, `--target 1..20`. Сайты проверяются последовательно, максимум три кандидата на организацию. Приоритеты берутся из обеих групп: без указанного сайта и с уже указанным сайтом. Непроверенный остаток явно учитывается в отчёте; число отобранных кандидатов может быть меньше 20.

### Режимы Overture и сохранённое исправление остановки

В 0.2 остановка только родительского процесса могла оставить рабочий процесс Overture и открытые потоки вывода. Поэтому таймаут и Ctrl+C не гарантировали завершение ожидания. В 0.2.1 на Windows применяется `taskkill /PID <PID этого запуска> /T /F` ко всему дереву; другие программы по имени не завершаются. CMD запускает Node напрямую, без промежуточного npm-процесса.

- Обычный запуск: `--overture cache`, **без сетевой выгрузки**. `--overture off` отключает и кэш.
- Явный онлайн-запуск: `npm.cmd run audit -- --limit 5 --overture online`. Выполняется после проверки известных сайтов и только для оставшихся неподтверждённых организаций.
- Онлайн: **до 60 секунд на процесс выгрузки**, **90 секунд общего бюджета на все города**, включая каталог и установку загрузчика, затем до **6 секунд на остановку дерева**. Лимит источника не включает время браузерного аудита сайтов. Это сокращение прежнего 300-секундного ожидания, не обещание ускорить Overture.
- Каждые 20 секунд: PID, прошедшее время, остаток лимита, размер выходного GeoJSON, время без вывода CLI и последнее сообщение инструмента. Размер GeoJSON — **не сетевой трафик**. Нулевой файл при чтении индексов возможен; сообщения о времени не означают продвижение загрузки. Процент инструмент не предоставляет.
- **Ctrl+C один раз** отменяет текущую загрузку, останавливает её дерево и сохраняет отчёт `interrupted`; новые города не запускаются. При обычном таймауте отчёт будет неполным (`partial`); другие доступные проверки могут продолжиться. Частичная выгрузка не считается успешным поиском и не заменяет кэш.
- Журнал `outputs/audit-.../diagnostics.log` создаётся до обращения к Overture. Его можно открыть Блокнотом даже во время работы. Перед передачей журнала проверьте локальные пути и названия организаций.
- Если Windows запретит `taskkill` или его завершение не подтвердится, программа сообщит PID, прекратит ожидание и не запустит другие загрузчики Overture в этом аудите. Проверьте указанный процесс в Диспетчере задач; не завершайте все `node.exe` или другие проекты.

Обновляйте файлы программы в прежней папке, сохраняя **outputs, .cache и .tools**. Запускайте снова `test-audit.cmd`; первый поиск повторять не требуется. Если сервер снова недоступен, пришлите `diagnostics.log` и `report.json` из нового запуска. Недоступность Overture не доказывает отсутствие сайта у организации.

### Что открыть после проверки

В новой папке `outputs/audit-.../`:

- **`report.html`** — удобный локальный отчёт с коротким списком, контактами, ссылками и скриншотами. Просто откройте в браузере.
- **`shortlist.csv`** — лучшие предварительные кандидаты: подтверждённые сайты с конкретными проблемами, затем организации, для которых сайт не обнаружен в проверенных источниках.
- `audit.csv` — все проверенные в этом запуске организации, включая неопределённые результаты.
- `audit.json`, `evidence/` — подробные совпадения, происхождение сайтов, HTTP-результаты и доказательства.
- `diagnostics.log` — журнал этапов, таймаутов и остановки загрузчика.
- `screenshots/` — снимки на 1440 и 390 px; `report.json` — состояние источников, ошибки, бюджет и счётчики.

В CSV отдельные колонки: **Телефон, Email, ВКонтакте, Telegram, MAX, WhatsApp, другие контакты**. Пустые значения не выдумываются. Из прежних `organizations.json` восстанавливаются явно сохранённые поля контактов, включая MAX и Telegram-имена; новый поиск для этого не нужен. Контакты, найденные на странице, добавляются только после подтверждения совпадения сайта с организацией. Источник каждого значения записывается в JSON. Также разделены «Подтверждённые наблюдения», «Предположения» и «Ошибки и ограничения»; HTML показывает их отдельно. Ни звонки, ни письма, ни сообщения не отправляются.

Пять организаций в `test-audit.cmd` — бюджет аудита, а не объём загрузки Overture: источник сначала читает общий индекс и данные района. В официальном CLI HTTP-чтение индекса не ограничено параметром S3 `--request_timeout`; внешний таймаут закрывает этот пробел; в обычном запуске 0.2.2 загрузка вообще не выполняется. Он не гарантирует скорость сервера. Подробности — в [SOURCES.md](SOURCES.md).

### Источник поиска сайтов и его ограничения

Независимый источник — **Overture Maps Places**, открытые данные, загружаемые официальным инструментом по географической области. Он содержит названия, адреса, координаты, телефоны и сайты. Это не переименование OSM-проверки: тест проверяет случай, когда сайт есть только в Overture и найден именно там. Дополнительно проверяются домены опубликованных корпоративных email; Gmail/Mail.ru/Яндекс и другие массовые почтовые домены исключены. Ссылки OSM сохраняются как отдельный тип источника.

У Overture неполное и не гарантированное покрытие российских компаний; это не поиск по всему Интернету и не актуальная база владельцев сайтов. У разных поставщиков разные открытые лицензии. Подробности, проверенные официальные источники, версия загрузчика и условия — в [SOURCES.md](SOURCES.md).

Название само по себе сайт не подтверждает. Нужны дополнительные совпадения телефона/email/адреса на самом сайте. Данные каталога сначала дают только кандидата. Если совпали несколько разных доменов, результат отправляется на ручную проверку. Соцсети и каталоги не считаются подтверждённым самостоятельным сайтом.

Статус **«Сайт не обнаружен, требуется подтверждение»** ставится только после успешного независимого поиска без найденных кандидатов. При недоступном источнике статус другой: **«Поиск сайта не завершён»**. Это исключает фиктивную проверку на основе пустого поля OSM.

### Что проверяет Playwright

Главную страницу, одну доступную ссылку «Контакты», совпадение данных организации, переполнение на ширине 390 px, настройку viewport, HTTP 404 изображений на странице и страницы контактов. Есть скриншоты и конкретные URL ошибок. Нет оценки «дизайн устарел», обещаний потока клиентов, проверки доставки заявок или отправки форм. Замер не заменяет полноценный аудит: краткая загрузка страницы, ограничения запросов и отложенный контент могут влиять на результат; перед предложением услуги просмотрите доказательства.

Учитывается robots.txt, включая безопасные перенаправления и Crawl-delay. 403/429 и CAPTCHA не обходятся. Разрешены только GET/HEAD; POST и WebSocket блокируются. Служебные/private IP и локальные адреса не проверяются. Ограничения доступа и сетевые ошибки **не считаются доказательствами плохого сайта** и не повышают приоритет.

Официальный загрузчик Overture использует PyArrow S3 без настраиваемого через CLI прокси. Если в среде заданы HTTP(S)/ALL_PROXY, модуль **не запускает потенциальное прямое соединение** и явно сообщает ограничение. Не отключайте корпоративный/обязательный прокси ради обхода правил. На обычном Windows-подключении без обязательного прокси этот барьер отсутствует. Из этой облачной среды свежую выгрузку подтвердить пока нельзя.

Общие тесты версии 0.2:

```powershell
npm.cmd run setup:audit
npm.cmd run check
npm.cmd test
```

На Linux можно указать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium`. Тесты используют только вымышленные записи и локальный сервер. Они не доказывают, сколько сайтов будет найдено для вашей выборки. Результаты проверок и пределы подтверждения описаны в [VALIDATION.md](VALIDATION.md).

## Запуск на Windows 11

1. Один раз установите **Node.js 24 LTS** (версия 24.5 или новее в ветке 24) с https://nodejs.org/. Перезапустите терминал/Codex после установки.
2. Откройте **эту папку** в Codex или терминале Windows и выполните:

```powershell
npm.cmd start
```

Для первого этапа поиска установка зависимостей по-прежнему не нужна. `npm.cmd` работает и при запрете PowerShell запускать `npm.ps1`. Альтернатива — двойной щелчок по `start.cmd`; окно останется открытым после завершения.

По умолчанию программа ищет в трёх зонах — Тверь (12 км от центра), Тула (15 км), Рязань (12 км). Это небольшие круги поиска, **не административные границы**. Возможны окрестности и неполные адреса. Поля «Зона поиска» и «Город в OSM» разделены; при явно другом городе запись не попадает в основную выборку.

Небольшое первое испытание, до пяти кандидатов из одной зоны:

```powershell
npm.cmd start -- --cities Тверь --target 5
```

Полный запуск обрабатывает все три зоны независимо от того, когда достигнут лимит. Поиск способен получить значительно больше 20 организаций; финальный `leads.csv` содержит максимум 20 предварительных кандидатов. Если их меньше, программа не выдумывает недостающие записи.

## Что появляется после запуска

Для каждого запуска создаётся **новая** папка `outputs/<время-UTC>-<идентификатор>/`. Старые результаты не перезаписываются.

| Файл | Содержимое |
| --- | --- |
| `leads.csv` | Название + распознанный опубликованный контакт + отсутствие поля сайта в OSM. Это повод проверить организацию, не доказательство отсутствия сайта. |
| `all-organizations.csv` | Все подходящие по категории объекты после фильтрации и удаления дублей, в том числе организации с сайтами. |
| `review.csv` | Остальные записи: сайты для будущего аудита, неполные контакты/названия, окрестности, кандидаты сверх лимита. |
| `organizations.json` | Доступные исходные поля OSM, источники каждого объединённого объекта, дата получения. |
| `report.json` | Выполненные запросы, счётчики, использование кэша и ошибки отдельно по городам. |
| `README.txt` | Краткий итог запуска и ограничения результатов. Сначала откройте его. |

CSV записывается в UTF-8 с BOM, разделитель `;`, строки CRLF — для русского Excel. Значения экранируются; формулы из внешних данных обезвреживаются. Если Excel не разделил колонки: **Данные → Из текста/CSV → UTF-8 → разделитель «точка с запятой»**. Телефоны сохраняются текстом.

### Критерии отбора

- Запрос ищет OSM-объекты `shop=car_repair`; это не полный каталог всех автосервисов. Шиномонтажи с другой категорией, отсутствующие в OSM компании и объекты с ошибочными тегами могут не попасть в выборку.
- Используются `name:ru`, `name`, `brand`, `operator`, доступные адресные поля, `website`/`contact:website`/`url`, телефоны, email, ссылки VK/Telegram/WhatsApp из соответствующих контактных полей.
- Формат контакта проверяется синтаксически. Доставка писем, работа номера, владение контактом и действующий статус бизнеса **не проверяются**. Дата получения данных не равна дате их последнего обновления владельцем.
- Заполненное, но некорректное поле сайта отправляет запись на проверку; оно не считается отсутствующим сайтом.
- У записей без поля сайта статус строго: «Сайт не указан в OSM; отсутствие сайта не подтверждено».
- Явно помеченные закрытыми/заброшенными объекты исключаются. Остальные могут оказаться устаревшими: OSM ведут участники сообщества.
- Сначала удаляются повторы по OSM ID. Другие записи объединяются только при одинаковом названии и убедительном совпадении адреса или контакта и близких координат. Один общий телефон/домен не объединяет удалённые филиалы. Сомнительные дубли могут остаться — лучше дополнительная проверка, чем потеря филиала.
- Кандидаты сортируются по заполненности контактов/адреса. Это **не оценка платёжеспособности, бюджета или желания купить сайт**.

## Бесплатные серверы, кэш и ограничения

Единственный внешний адрес **первого этапа `npm start`**: `https://overpass-api.de/api/interpreter`. Поисковый модуль отправляет туда только запросы к открытым данным. Вторая команда `npm run audit` проверяет публичные сайты и кэш Overture; с `--overture online` дополнительно обращается к Overture, как описано выше. Сообщения и письма не отправляются; языковые модели не вызываются.

- Один экземпляр программы за раз; запросы последовательные.
- Пауза между сетевыми запросами минимум 15 секунд, в том числе между последовательными запусками в этой папке.
- Успешный ответ кэшируется на 7 дней. В отчёте видны кэш и первоначальная дата получения.
- По умолчанию три небольших запроса, а не обход всех городов страны. Публичный сервер не даёт SLA; доступность и действующие правила необходимо учитывать при расширении.
- HTTP 429 останавливает поиск, `Retry-After` сохраняется на диск. При отсутствии заголовка — пауза 30 минут. `--refresh` эту паузу не отменяет.
- HTTP 401/403/407 останавливает дальнейшие запросы. Автоматической смены серверов/IP, обхода CAPTCHA или блокировок нет.
- Для 502/503/504 без требования долгой паузы — максимум одна повторная попытка через 30 секунд. Запрошенный сервером `Retry-After` соблюдается.
- Лимит ожидания одного запроса с чтением ответа — 45 секунд; объём ответа — 16 МБ. `remark` с ошибкой Overpass означает неполный ответ: его данные не выдаются за успешные и не кэшируются.
- TLS-проверка включена. `--use-env-proxy` позволяет Node.js использовать системные переменные прокси; программа не отключает и не обходит прокси.
- Не запускайте параллельные копии в разных папках ради обхода ограничений. Не удаляйте `.cache/network-state.json` ради отмены паузы сервера.

Обновление действующего кэша при необходимости:

```powershell
npm.cmd start -- --refresh
```

## Ошибки и прерывание

Коды завершения: **0** — все выбранные зоны обработаны (даже если организаций нет); **2** — поиск неполный или заблокирован; **1** — параметры/локальная ошибка; **130** — остановка Ctrl+C.

Если получена только часть городов, хорошие результаты сохраняются, статус — `partial`. Если доступ отсутствует с первого запроса, статус — `failed`, а пустой CSV **не означает отсутствие компаний**. Смотрите `report.json` и `README.txt` в новой папке запуска. Реальные данные не подменяются тестовыми.

Ctrl+C сохраняет уже полученные результаты. Если нажать его во время паузы, сохранение может занять до 30 секунд. После аварийного завершения устаревшая блокировка удаляется автоматически, если PID процесса больше не существует. Если повреждён `.cache/run.lock`, сначала убедитесь, что нет другого запущенного поиска, затем удалите **только этот файл**, не кэш ограничения частоты.

При `NETWORK`/`ACCESS_DENIED` проверьте обычное соединение и разрешение `overpass-api.de` в настройках своей среды. Не отключайте сертификаты или защиту. Можно запускать на Windows с обычным разрешённым подключением. При проблемах самого публичного сервера повторите запуск позднее; программа не обещает определённое число организаций.

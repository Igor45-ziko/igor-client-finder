# Короткое испытание ссылок, не новая версия разведчика

Экспериментальная ветка `diagnostic/card-link-trial`. Рабочая версия остаётся 0.2.5.
Проверенные карточки и независимый поиск организаций без сайта пока **не получены**.
Не используйте результат как готовый список потенциальных клиентов.

## Запуск на уже работающем Windows 11

Скачайте **только два файла** этой ветки — `probe-card-links.cmd` и
`probe-card-links.mjs` — в папку установленного `igor-client-finder` рядом с
`package.json`. Не заменяйте папки проекта. Запустите `probe-card-links.cmd`.
Используются уже установленные Node.js 24, Playwright и Edge/Chromium.
Установок, загрузки компонентов и изменения защитных настроек нет.

До четырёх минут плюс до шести секунд для остановки дерева процессов.
Результат откроется в браузере; отдельная папка `igor-card-trial-*` создаётся
в системном `%TEMP%`. Сохраните из неё `trial.json`, если нужен разбор.
При принудительной остановке там же остаётся `interrupted.txt`.
`outputs`, `.cache`, `.tools` и прежняя база не читаются и не изменяются.
Временный кэш пробы находится исключительно внутри её новой папки.

## Один проверяемый способ

1. Через прежний публичный Overpass получаем до 20 OSM-записей с опубликованными
   сайтами/ссылками в каждом из двух административных регионов: Москва и
   Московская область. Это ограниченный срез, **не полный охват области**.
2. Берём не более трёх организаций каждого региона. Сначала пробуем записи с
   уже опубликованными полными ссылками на карточки. OSM здесь только источник
   исходных записей и ссылок, а не независимое подтверждение отсутствия сайта.
3. У организации проверяем первый сайт-кандидат существующим аудитором
   (до 25 секунд): название + контакт/адрес, главная/контакты, мобильное
   переполнение, HTTP 404 изображений, до двух внутренних страниц.
   Из подтверждённого сайта извлекаем фактические ссылки на Яндекс/2ГИС.
   Не конструируем URL из названия или ID. Короткие ссылки не разворачиваются.
4. Сам Яндекс/2ГИС автоматически не опрашивается: разрешение на сбор карточек
   и выдачи не установлено. Нужна обычная ручная проверка только найденных
   ссылок и соответствия филиала. Остановка на капче/входе/запрете доступа;
   обходов, внутренних API, чужих ключей и автоматических сообщений нет.

Отчёт показывает только название, прямую найденную ссылку, статус сайта
и конкретные проблемы с URL. Адреса/контакты не выносятся в основной список.
Ссылка из сайта сети может вести на другой филиал: она остаётся **непроверенной**.
HTTP 200/совпадение названия само по себе не подтверждает филиал.

## Что проверка не решает

Этот способ прежде всего пригоден для дополнительной задачи — проблемных
сайтов. Нельзя ожидать, что сайты организаций станут источником компаний
без сайта. Отсутствие ссылки в OSM, в закрытом поле API или ошибка проверки
не приводят к статусу «сайт не обнаружен». Для него по-прежнему нужна
успешная независимая проверка конкретной организации в доступных источниках.
Условия поисковых систем/каталогов не подтверждены; их скрейперы не добавлены.

Программа соблюдает существующие ограничения robots.txt, публичных адресов,
TLS, прокси, частоты и времени. robots.txt не заменяет условия сайта;
не запускайте против источника, условия которого запрещают такую проверку.
Никакой Overture. Источники OSM: © OpenStreetMap contributors, ODbL 1.0.

## Условие перехода к интеграции

Нужны несколько ссылок, которые действительно открывают правильные карточки,
и результаты сопоставления сайтов/дефектов. Если ссылок нет, способ не прошёл
проверку на выборке; увеличивать её бесконечно нельзя. Выпуск/ZIP не обновляются.
Локальные автоматические тесты используют искусственные данные и не заменяют
это испытание. Из облака публичные источники закрыты сетевой политикой;
Windows в этой среде не доступна.
